### 任务二｜阶段 B 首批：系统调用错误检查 + 套接字健壮性（B1 + B2）

- **状态**：🟡 已派发（@ 2026-09-03）
- **背景与痛点**：阶段 A 解决"看着像工程"，阶段 B 解决"**不会挂**"。当前 `socket/bind/listen/accept/epoll_create/epoll_ctl/epoll_wait/eventfd/read/write` 全部**零错误检查**（失败静默吞掉）；无 `SO_REUSEADDR` → 服务重启遇 TIME_WAIT 直接 `bind` 失败起不来；无 `SIGPIPE` 忽略 → 对端关闭后 `write` 会**杀死整个进程**；`epoll_wait/accept/read` 无 `EINTR` 重试 → 被信号打断即异常返回。均为"线上必挂"级，需在本阶段根除。
- **任务范围（B1 + B2，纯健壮性加固，不加新行为）**：
  1. 系统调用错误检查全覆盖：对上述每个系统调用做返回值检查；失败路径输出错误并优雅处置（如 `bind/listen` 失败需 `close(fd)` 后再退出/抛错，**杜绝 fd 泄漏**）。
  2. `SO_REUSEADDR`：acceptor 的 listen socket 开启 `setsockopt`。
  3. `SIGPIPE`：进程级 `signal(SIGPIPE, SIG_IGN)`（在库初始化/服务入口一次）。
  4. `EINTR` 重试：`epoll_wait/accept/read/write` 在 `errno == EINTR` 时重试。
  5. 纪律：延续任务一"不改正确路径行为"——只新增**失败分支检查**与**前置配置**，成功路径逻辑保持不变。
- **验收标准（Acceptance Criteria）**：
  - [ ] grep 抽查 `muduo/src/`：所有关键系统调用均有返回值/`errno` 检查
  - [ ] 杀掉 server 后立即重启 `bind` 成功（无 `SO_REUSEADDR` 时会失败）
  - [ ] 对端断开后本端继续 `write`，进程不崩（SIGPIPE 已忽略）
  - [ ] `-Wall -Wextra -Wpedantic` **零警告**
  - [ ] `test_main` echo 行为无回归（收到连接并完整打印）
- **技术提示（不写代码）**：
  1. **错误处理先收口**：先建最小错误工具（如 `src/syserr.h` 提供统一 `CHECK_SYS/LOG_SYSERR`），一处风格统一；后续 D4 正式 Logger 再替换。勿逐处手写风格各异的 `if + printf`。
  2. **错误路径资源纪律**：任何在 fd 创建成功后失败的分支，都要先释放已分配资源再返回/抛出。
  3. **SIGPIPE 二选一权衡**：全局 `SIG_IGN` 简单但影响整个进程；`MSG_NOSIGNAL` 精准但需逐写点处理。网络库推荐 `SIG_IGN` + 文档标注；若坚持库内自治则写入统一走 `MSG_NOSIGNAL`。选定一种并说明理由即可。
